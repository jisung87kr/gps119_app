# 00. 마스터 실행 플랜 (Master Plan) — 실시간 위치·지령 관제

> 이 문서는 에픽 [README](../README.md) 및 [09-roadmap](../09-roadmap.md)에서 **확정된 설계를 실행 단위로 변환**한 것이다.
> 설계를 다시 열지 않는다. 여기서는 "누가 / 무엇을 / 어떤 순서로 / 무엇이 막히면 다 막히는지"만 다룬다.
> 추정은 모두 **상대 규모(S/M/L)** 또는 **상대 주(week)** 다. 절대 날짜는 만들지 않는다.

## 0. 워크스트림 · lane 접두사

태스크는 4개 워크스트림으로 쪼갠다. 세부 태스크 파일은 다른 담당이 lane 접두사로 채운다.

| Lane | 워크스트림 | 1차 담당 | 다루는 것 |
|------|-----------|----------|-----------|
| **OPS-** | 인프라/운영 | kang-mansu (DevOps) | Reverb 데몬, 큐 워커, 도커 WS 프록시, supervisor, 배포, 보존정책 자동화 |
| **BE-** | 백엔드 | na-minsik(설계) → kim-balsu(구현) | 마이그레이션, Enum, Service, API, 브로드캐스트 이벤트, 채널 인가 |
| **FE-** | 프론트엔드 | kim-balsu | 참가자 PWA, 구급대 앱, 웹 관제 SPA, Echo 클라이언트, 카카오맵/내비 |
| **DS-** | UX/디자인 | lee-sunja | 입장·신고·지령 플로우, 관제 레이아웃, 주소확인 모달, 마커 디자인 시스템, 접근성 |

> 규모 표기: **S** ≈ 1주 미만 · **M** ≈ 1~2주 · **L** ≈ 2주+. 상대값이며 인원·병렬도에 따라 압축 가능.

## 1. 마일스톤 M0 ~ M4

각 마일스톤은 [09-roadmap](../09-roadmap.md)의 Phase와 1:1 대응한다. **DoD(Definition of Done)** 는 "동작하는 수직 슬라이스"를 기준으로 한다.

### M0 — 실시간 기반 (Phase 0)
- **목표**: WebSocket이 살아 있고, 기존 신고가 실시간으로 관제에 뜬다.
- **DoD**
  - [ ] `BROADCAST_CONNECTION=reverb`, Reverb 데몬이 도커에서 기동·헬스 감시된다.
  - [ ] Echo 클라이언트가 `/broadcasting/auth` 인가를 통과해 채널을 구독한다.
  - [ ] 큐 워커(`queue:work`)가 상시 가동되고 브로드캐스트가 비동기로 나간다.
  - [ ] `RequestCreated`가 `event.{id}.control` 채널로 나가 관리자 화면에 토스트로 뜬다(PoC).
  - [ ] WS 실패 시 HTTP 폴링 폴백이 동작한다.
- **의존**: 없음 (선행 필수, 크리티컬 패스 시작점)
- **기간**: M · ADR-0001 적용

### M1 — 행사 입장·역할 (Phase 1)
- **목표**: 코드/QR로 행사에 입장하면 행사 스코프 역할이 부여된다.
- **DoD**
  - [ ] `projects.join_code` + `event_participants` 마이그레이션, `EventParticipant` 모델, `EventRole` enum.
  - [ ] `GET/POST /api/events/{joinCode}` + `/join` + `/me` 동작.
  - [ ] `event.role` 미들웨어가 `bootstrap/app.php`에 등록되고 권한 역할은 `active` 전까지 차단된다.
  - [ ] 참가자 앱 입장 플로우(코드입력/QR → 로그인 복귀 → 역할표시).
  - [ ] 역할 배정 3경로(자가선택 / 사전명단 매칭 / 수동) 중 자가선택+수동 동작(사전명단은 데이터소스 결정 후).
- **의존**: M0
- **기간**: M · ADR-0002 적용

### M2 — 실시간 위치 관제 지도 (Phase 2)
- **목표**: 관제 지도에서 전 인원이 역할 색상으로 실시간 이동한다.
- **DoD**
  - [ ] `location_pings` + `event_participants.last_*` 마이그레이션, 위치 ping API, 큐 적재(append-only).
  - [ ] 참가자 앱 `watchPosition` 적응형 자동 공유 + 공유 토글.
  - [ ] `ParticipantLocationUpdated` 브로드캐스트(`locations`/`control`).
  - [ ] 웹 관제 v1: 카카오맵 + 전 인원 마커(초기 1쿼리 로드) + 역할 필터 + online/offline.
  - [ ] 마커는 좌표만 이동(전체 리렌더 금지), 대규모 시 클러스터링.
- **의존**: M1 (역할·스코프 없이는 마커 분류/인가 불가)
- **기간**: L · 요구 surface 3번의 핵심

### M3 — 신고 고도화·지령 상태머신 (Phase 3) ★ 핵심 가치
- **목표**: 신고 → 지령 → 출동 → 완료 전 과정이 실시간으로 돈다.
- **DoD**
  - [ ] `RequestType` enum + `requests.type`, 신고 버튼/주소확인 모달 개편.
  - [ ] `dispatches` + `DispatchStatus` + `DispatchService`(전이 검증) + Dispatch API.
  - [ ] 구급대 앱: 지령 풀스크린 수신(알림음/진동), 수락→출동→도착→완료 전이, 카카오내비(고정좌표).
  - [ ] 관제: 지령 배정 UI(가용 대원 거리순) + 출동 현황 보드 실시간 집계.
  - [ ] 신고자: 상태 실시간 추적 + 담당자 전화 연결(`tel:`).
  - [ ] 채널별 연락처 노출 범위가 ADR-0004대로 강제된다(구급대는 control 미구독).
  - [ ] 신고 status ↔ 지령 status 동기화가 `DispatchService`에 단일화된다.
- **의존**: M2
- **기간**: L · ADR-0003·0004 적용

### M4 — 마감·운영 (Phase 4)
- **목표**: 기록을 내려받을 수 있고, 하이브리드로 운영 안정화된다.
- **DoD**
  - [ ] 기록 다운로드 확장(신고 CSV·지령 타임라인·동선 비동기 생성).
  - [ ] PWA 마감(매니페스트/서비스워커/설치 온보딩), 알림 권한.
  - [ ] Capacitor 하이브리드 래핑: 백그라운드 위치추적·푸시(FCM).
  - [ ] 부하/배터리 튜닝, Reverb 스케일링(Redis) 검증, 위치이력 보존·자동파기 정책 가동.
- **의존**: M3
- **기간**: L

| MS | 한 줄 | 의존 | 기간 | 적용 ADR |
|----|-------|------|------|----------|
| M0 | 실시간 신고 수신 동작 | — | M | 0001 |
| M1 | 행사 코드 입장·역할 | M0 | M | 0002 |
| M2 | 전 인원 실시간 관제 지도 | M1 | L | — |
| M3 | 지령 상태머신 end-to-end | M2 | L | 0003·0004 |
| M4 | 기록 다운로드 + 하이브리드 | M3 | L | — |

## 3. RACI

R=실행 · A=최종책임(1인) · C=자문 · I=공유. PM(cha-sunok)은 전 항목 일정/리스크/합의의 A 또는 C.

| 활동 | na-minsik (아키텍트) | kim-balsu (풀스택) | kang-mansu (DevOps) | lee-sunja (디자이너) | PM |
|------|----------------------|--------------------|---------------------|----------------------|----|
| 실시간 인프라(Reverb/큐/프록시) OPS-* | C | I | **A/R** | — | A(일정) |
| 데이터 모델·마이그레이션 BE-1.1/2.1/3.1 | **A** | R | C | I | C |
| Enum·Service·전이검증 BE-3.2 | **A** | R | I | — | C |
| API·채널 인가·미들웨어 BE-* | A | **R** | C | I | C |
| 브로드캐스트 이벤트·페이로드 BE-2.2/3.3 | **A** | R | C | I | C |
| 참가자/구급대 앱 FE-1·2·3 | C | **A/R** | I | C | C |
| 웹 관제 SPA FE-2.1/3.3 | C | **A/R** | I | C | C |
| 입장/신고/지령/관제 UX DS-* | C | C | — | **A/R** | C |
| 디자인 시스템·마커·접근성 DS-* | I | C | — | **A/R** | I |

## 4. 크리티컬 패스

가장 늦어지면 전체가 늦어지는 단일 경로. **모두 직렬 의존**이라 병렬화로 줄일 수 없는 사슬이다.

```
OPS-0.1(Reverb/도커 WS)
   → BE-0.1(withBroadcasting·채널 교체)
   → FE-0.1(Echo·폴백 PoC)            ── M0
   → BE-1.2(입장 API·event.role 가드)  ── M1  [BE-1.1 스키마는 M0와 병렬 선행]
   → BE-2.1(위치 ping·큐 적재)
   → BE-2.2(ParticipantLocation 이벤트)
   → FE-2.1(웹 관제 SPA v1)           ── M2  [가장 무거운 L 단일 태스크]
   → BE-3.2(dispatches·DispatchService)
   → BE-3.3(지령 이벤트·채널 분리)
   → FE-3.2(구급대 앱 지령 end-to-end) ── M3  ★ 핵심 가치 완성
   → BE-4.1/FE-4.1(리포트·PWA) → OPS-4.2(하이브리드) ── M4
```

> **한 줄**: `OPS-0.1 → BE-0.1 → FE-0.1 → BE-1.2 → BE-2.1 → BE-2.2 → FE-2.1 → BE-3.2 → BE-3.3 → FE-3.2`가 M0~M3 핵심가치까지의 크리티컬 패스이며, 가장 무거운 병목은 **FE-2.1(관제 SPA)** 과 **BE-3.2(지령 상태머신)**.

**병목 완화 (병렬 착수 가능)**
- BE-1.1(스키마)·DS-1.1/2.1/3.1(디자인)·OPS-0.2(큐)는 크리티컬 사슬과 **병렬 선행**해 둔다.
- DS lane은 항상 대응 FE보다 한 발 앞서 준비(FE가 디자인 대기로 멈추지 않게).

## 6. 착수 전 열린 결정사항

[09-roadmap](../09-roadmap.md) '열린 결정사항' + ADR 미결분. **표시된 것은 해당 마일스톤 착수 전 합의 필요.**

| # | 결정사항 | 막는 마일스톤 | 결정 필요 주체 | 비고 |
|---|----------|----------------|----------------|------|
| Q1 | 사전명단 배정 데이터 소스(전화번호 CSV vs 외부연동) | M1 | PM + 고객/운영진 | 미정 시 M1은 자가선택+수동만으로 출시 가능(부분 진행) |
| Q2 | 위치이력 보존기간(법무 검토) | M2 | **PM(법무 자문)** | R3·자동파기 잡(OPS-4.1) 설계 선행조건 |
| Q3 | 구급대원 가용성 판단 기준(거리만 vs 현재 지령 보유수) | M3 | na-minsik + 운영진 | FE-3.3 배정 UI 정렬 로직 결정 |
| Q4 | 행사 동시 운영 규모(단일 Reverb로 충분한가) | M4(M2서 조기검토) | kang-mansu | ADR-0001 "초기 단일 인스턴스" 전제의 유효성. R2와 연동 |
| Q5 | OpenAPI/Swagger 도입 여부·시점 | M1(API 본격화 전) | na-minsik | 08 문서 "도입 권장"이나 미확정 — 도입하면 모든 BE API에 어노테이션 부담 |
| Q6 | 기존 `assign` 라우트 폐기(Deprecated→제거) 시점 | M3 | na-minsik | ADR-0003: 지령 API 안정화 후 제거 — 제거 트리거 합의 필요 |
| Q7 | 푸시 전략: 인앱(Reverb) → 백그라운드(FCM) 전환 경계 | M4 | kang-mansu + PM | 05 문서상 하이브리드 단계로 미룸 — 범위/일정 영향 |

> **변경관리 원칙**: 위 결정이 합의 없이 바뀌면 scope creep으로 본다. 변경은 반드시 영향(일정·범위)과 함께 PM 합의 후 [09](../09-roadmap.md) 또는 새 ADR로 반영한다.
