# 디자인 스펙 — 웹 관제 지도 (DS-2.1 / DS-2.2 구현 지침)

> 대상: kim-balsu(풀스택, FE-2.1). 이 문서는 [ux-tasks.md](../ux-tasks.md) DS-2.1·DS-2.2를 **그대로 구현 가능한 수준**으로 구체화한 것이다.
> 코드가 아니라 구현 지침이다. 토큰은 Tailwind 클래스/hex로 확정해 FE가 바로 쓰게 한다.
> 근거 문서: [07-web-control.md](../../07-web-control.md), [02-roles-and-access.md](../../02-roles-and-access.md), [architecture-spec.md](../architecture-spec.md) SPEC-02a/05, [open-decisions.md](../open-decisions.md) DS-color.

## 0. 전제 · 제약

- **PC 대화면 전용.** 태블릿/모바일 관제는 06 축약형(별도). 이 화면은 **최소 1280px**, 기준 설계폭 **1920 / 1440**. 1280 미만은 가로 스크롤 허용(반응형 분기 없음 — 현장 지휘 데스크톱 전제).
- **새 디자인시스템 발명 금지.** 기존 톤 계승: `admin/requests/index.blade.php`의 blue-600 primary, WS/폴링 green/amber 인디케이터(35행), `border-l-4` 토스트(14행), `rounded-lg shadow`. 카카오 SDK는 이미 `libraries=services,clusterer,drawing`으로 로드됨(7행) → **clusterer 라이브러리 그대로 사용**.
- **색만으로 의미 전달 금지(DS-color 결정).** 역할 7종은 **색 + 아이콘 형태** 병용. 아이콘은 Heroicons(outline/solid) 차용, 신규 제작 최소.
- **Enum 헬퍼에 귀속.** 마커색은 `EventRole::markerColor()`(SPEC-02a), 신고핀 아이콘은 `RequestType::markerIcon()`(SPEC-02c). 화면 코드는 hex를 직접 박지 않고 enum/페이로드 `role`·`type`으로 lookup.
- **연락처(ADR-0004).** 관제는 controller/admin 화면이므로 노출 허용. 단 **노출 위치를 §7로 한정**.

## 1. 레이아웃 그리드 (07 ASCII → 실제 비율)

```
┌─────────────────────────────────────────────────────────────────────────┐
│ HEADER  h:56px  ·  [행사 ▼]  실시간 관제 — {행사명}    온라인 42 · 신고 3 │ ●WS
├──────────────┬──────────────────────────────────────────────────────────┤
│  L-RAIL      │                      MAP (카카오맵)                        │
│  w:280px     │                      flex-1 (잔여 전체)                     │
│  고정         │                                                          │
│ ┌──────────┐ │                  · 역할 마커 / 신고 고정핀                  │
│ │역할 필터  │ │                  · 클러스터러                              │
│ │(체크 7)   │ │                                                          │
│ ├──────────┤ │                                                          │
│ │인력 현황  │ ├──────────────────────────────────────────────────────────┤
│ │(역할 카운트)│ │  BOTTOM  h:240px (가변 200~320, 드래그 리사이즈)           │
│ │          │ │  ┌────────────────────────┬───────────────────────────┐  │
│ │          │ │  │ 신고 접수 목록 (flex 3) │ 출동 현황 보드 (flex 2)    │  │
│ └──────────┘ │  └────────────────────────┴───────────────────────────┘  │
└──────────────┴──────────────────────────────────────────────────────────┘
```

| 영역 | 크기 | 우선순위 | 내용 |
|------|------|----------|------|
| **HEADER** | 높이 `56px` 고정, 전폭 | 항상 표시 | 좌: 행사 선택 드롭다운 + "실시간 관제 — {행사명}". 우: KPI(온라인 N·신고 N) + WS/폴링 인디케이터(green/amber dot, 기존 35행 패턴). |
| **L-RAIL** | 폭 `280px` 고정, 세로 100% | 항상 표시(접기 토글 → `48px` 아이콘레일) | 상단 **역할 필터**(§4), 하단 **인력 현황**(역할별 online/total 카운트). 세로 스크롤. |
| **MAP** | `flex-1`(잔여 전부), 세로 = 전체−BOTTOM | 주인공 | 카카오맵. 마커·핀·클러스터(§3). 우상단 floating: 범례 토글·"지도 중심복귀"·줌. |
| **BOTTOM** | 높이 `240px`(가변 `200~320`, 상단 핸들 드래그 리사이즈), 폭 = MAP과 동일 | 종속 | 좌 **신고 접수 목록**(flex 3) / 우 **출동 현황 보드**(flex 2). BOTTOM 접으면 MAP이 세로 100%. |

- **그리드 구현**: 최상위 `grid grid-cols-[280px_1fr] grid-rows-[56px_1fr]`. L-RAIL은 `row-span-2`. 우측 컬럼 내부는 `grid grid-rows-[1fr_240px]`(MAP/BOTTOM).
- **스크롤 정책**: MAP은 절대 페이지 스크롤 유발 금지(`overflow-hidden`, 지도 자체 줌/팬만). L-RAIL·BOTTOM 패널만 내부 스크롤.
- **배경/카드 톤**: 패널 `bg-white border border-gray-200 rounded-none`(관제는 풀블리드라 외곽 라운드 없음, 내부 카드만 `rounded-lg`). 구분선 `border-gray-200`.

## 2. 역할 마커 시스템 (EventRole 7종 — 색 + 형태 병용)

`EventRole::markerColor()`가 반환할 hex와, 마커에 얹을 Heroicons 형태를 1:1로 확정한다. **인접 역할은 색뿐 아니라 아이콘으로도 구분**(색맹 대비).

| EventRole | 라벨 | 마커색 hex | Tailwind 근사 | 아이콘(Heroicon) | 형태 의미 |
|-----------|------|-----------|---------------|------------------|-----------|
| `participant` | 참가자 | `#6B7280` | gray-500 | `user` (단일 인물) | 기본·무채에 가까운 중립 |
| `staff` | 운영진 | `#2563EB` | blue-600 | `identification` (명찰) | 운영 = 파랑(기존 primary 계열) |
| `police` | 경찰 | `#1E3A8A` | blue-900 | `shield-check` (방패) | 공권력 = 진남색 방패 |
| `volunteer_course` | 자원봉사자(코스) | `#16A34A` | green-600 | `flag` (코스 깃발) | 코스 운영 = 초록 깃발 |
| `volunteer_medic` | 자원봉사자(구급) | `#F59E0B` | amber-500 | `plus-circle` (구급 +) | 구급 보조 = 주황 +원 |
| `paramedic` | 구급대 | `#DC2626` | red-600 | `plus` solid bold (구급 +) | 정식 구급 = 빨강 +(굵게) |
| `controller` | 상황실 | `#7C3AED` | violet-600 | `command-line`/`signal` (관제) | 지휘 = 보라 |

**색맹 구분 핵심 (검증 완료)**:
- 구급 계열 둘(`volunteer_medic` 주황 / `paramedic` 빨강)은 색이 인접 → **둘 다 `+` 아이콘이되 medic은 `plus-circle`(원테두리), paramedic은 굵은 solid `plus`**로 형태 분리.
- 파랑 계열 둘(`staff` blue-600 / `police` blue-900)은 명도차 + **명찰 vs 방패** 형태로 분리.
- 적록색맹: 빨강(paramedic)·초록(volunteer_course)이 헷갈릴 수 있으나 **+ vs 깃발** 형태가 결정적 구분.

**마커 시각 규격**:
- 형태: `pin`(물방울 핀, 하단 꼭짓점이 좌표) 안에 흰색 아이콘. 크기 `32×40px`(아이콘 18px).
- 라벨: 줌 ≥ 5(상세)일 때만 마커 아래 이름/역할 텍스트 `text-xs bg-white/90 rounded px-1`. 줌 작으면 핀만.
- **상태 뱃지 팔레트와 충돌 회피**: 역할 마커색은 **지도 전용 팔레트**로 격리. 신고/지령 **상태 뱃지**는 기존 `RequestStatus/DispatchStatus::badgeClasses()`(amber/blue/emerald/slate)를 그대로 쓴다. 즉 "보라=상황실 마커"와 "blue 뱃지=진행중 상태"는 문맥(지도 vs 리스트)이 달라 혼동 없음. **리스트/보드에서는 역할색을 쓰지 않는다**(역할은 아이콘+라벨로만).

## 3. 마커 종류 구분 (인원 / 신고핀 / 출동중)

세 종류가 **색을 무시해도 형태로 구분**되어야 한다.

| 종류 | 형태 | 크기 | z-index | 상태 표현 |
|------|------|------|---------|-----------|
| ① **인원 이동마커** | 물방울 핀(§2 역할색+아이콘) | 32×40 | `z: 10` | online=불투명·실선 테두리(`#fff` 2px). offline/stale=불투명도 40% + 점선 테두리 + 회색조(grayscale). |
| ② **신고 고정핀** | **각진 경고 핀**(인원과 형태 자체가 다름: 둥근 핀 아님, 마름모/경고 삼각 베이스) + 점멸 | 40×48(가장 큼) | `z: 100`(항상 최상단, 클러스터에도 안 묻힘) | **점멸 애니메이션**(`animate-pulse` 또는 ring scale 0→1 반복). 색 = 신고 우선순위(§6). 미처리(pending)만 점멸, 처리중(in_progress)은 점멸 정지+테두리만, 완료(completed)는 반투명 핀. |
| ③ **출동중 구급대원** | 인원 이동마커(paramedic 빨강 +) + **경로 강조** | 32×40 + 경로 | `z: 50`(인원보다 위, 신고핀보다 아래) | 마커에 펄스 링 1겹 + 해당 구급대원→신고 고정핀 사이 **점선 폴리라인**(`#DC2626`, dash). dispatch.status가 `en_route/arrived`인 대원만. |

**①②의 결정적 구분(핵심)**: 인원은 **둥근 물방울 핀**, 신고는 **각진 경고 핀 + 점멸**. 모양 자체가 다르므로 색맹·흑백에서도 "사람 위치"와 "사고 지점"이 즉시 구분된다. 신고핀은 항상 z-100이라 1000개 마커 클러스터 속에서도 떠 보인다.

**렌더 원칙(07/03 정합)**: 마커는 **좌표만 이동**(전체 리렌더 금지). `participant.location` 수신 시 `userId → MarkerObject` 맵에서 해당 마커의 `setPosition`만 호출. 신고핀은 신고 스냅샷 고정좌표(03 불변)라 **절대 이동 안 함** — 이동 코드 경로에서 신고핀 제외.

## 4. 역할 필터 UX

```
┌─ 역할 필터 ────────────┐
│ [전체] [해제]          │   ← 토글 2버튼
│ ●  참가자        (38)  │   ← ● = 마커색 미리보기 dot, (n)=online 수
│ ●  운영진         (4)  │
│ ●  경찰           (2)  │
│ ●  자봉(코스)     (6)  │
│ ●  자봉(구급)     (3)  │
│ ●  구급대         (5)  │
│ ●  상황실         (1)  │
└────────────────────────┘
```

- **체크박스 7개**, 각 행 = `[체크박스] [역할색 dot] [라벨] [online 카운트]`. dot 색 = `EventRole::markerColor()`(필터와 지도 색 일관 시각 확인).
- **즉시 반영**: 토글 시 해당 역할 마커 `setMap(null)`/`setMap(map)`만(리렌더 없음). 클러스터러도 해당 마커 add/remove.
- **[전체]/[해제]**: 7개 일괄 on/off. 0개 선택 시 지도 위 안내 토스트 "표시할 역할이 없습니다".
- **카운트**: `(online수)` 기본. 호버 툴팁에 `online/total`(예: 5/7). 카운트는 `last_seen_at` 기반 online 판정(§6)으로 실시간 갱신.
- **신고핀은 역할필터와 무관**(항상 표시). 필터는 인원 마커에만 작용.

## 5. 클러스터링 규칙 (수백~수천 마커)

카카오 `MarkerClusterer`(이미 로드됨) 사용. 줌레벨은 카카오 기준 **숫자 작을수록 확대**.

| 줌레벨(카카오) | 동작 |
|----------------|------|
| `≤ 4` (상세) | **개별 마커** 전부 표시 + 라벨. 클러스터 해제. |
| `5 ~ 7` (중간) | 클러스터링 on. `minClusterSize: 10`, `gridSize: 80`. 클러스터 버블에 인원수. |
| `≥ 8` (광역) | 강한 클러스터링. `gridSize: 120`. 버블만(개별 핀 숨김). |

- **클러스터 버블 디자인**: 원형 `bg-blue-600/90 text-white`, 숫자. 크기 단계(10/50/100/500↑)별 지름 `36/44/52/60px`. **역할 혼합 클러스터**는 단색 파랑(역할색 섞지 않음 — 혼동 방지). 단일 역할만 모인 클러스터는 그 역할색 테두리 2px로 힌트(선택, 구현 여유 시).
- **신고 고정핀은 클러스터 제외**(`clusterer.addMarkers`에 인원만 add, 신고핀은 별도 일반 마커로). 신고는 몇 개뿐이고 z-100이라 항상 개별 표시.
- **화면밖 가상화**: 뷰포트 밖 마커는 카카오가 자동 컬링하지만, **마커 객체 생성은 초기 1쿼리(`event_participants.last_lat/lng`, 07/03) 전량 생성**하되 `setMap`은 뷰포트+버퍼만 부착하는 풀 재사용 패턴 권장. 수천 규모에서 매 ping마다 새 마커 금지 — `userId` 키 마커풀 갱신.
- **성능 가드(R2 연동)**: ping 수신은 최신값만 반영(중간값 버림). 16ms 프레임 내 다수 ping 오면 `requestAnimationFrame` 배칭 후 일괄 `setPosition`.

## 6. 상태 표현 (online/stale/우선순위/빈·로딩·에러)

### online / offline / stale
- 판정: `last_seen_at` 기준. `≤ 30s` = **online**(불투명·실선). `30s ~ 120s` = **stale**(불투명도 60% + 점선 테두리, "위치 지연" 의미). `> 120s` = **offline**(불투명도 30% grayscale, 또는 필터에서 제거 — 토글로 "오프라인 숨기기" 제공).
- 인력 현황 카운트는 online만 집계.

### 신고 우선순위별 핀 색 (RequestType/priority 일관)
신고 고정핀 색은 **priority**(SPEC-02c `defaultPriority` 매핑)로:

| priority | 핀 색 hex | Tailwind | 점멸 |
|----------|-----------|----------|------|
| `critical`(긴급) | `#DC2626` | red-600 | 빠른 점멸(0.8s) |
| `high`(사고) | `#EA580C` | orange-600 | 보통 점멸(1.2s) |
| `medium`(고장) | `#F59E0B` | amber-500 | 느린 점멸(1.6s) |
| `low`(기타) | `#6B7280` | gray-500 | 점멸 없음(정적) |

- 핀 **안 아이콘**은 `RequestType::markerIcon()`(사고/고장/기타/긴급 형태) → 같은 빨강(긴급/사고)도 아이콘으로 구분. 색=긴급도, 아이콘=유형.
- 처리 상태(`RequestStatus`)는 점멸로: pending=점멸, in_progress=점멸정지+굵은 테두리, completed=반투명·이력행 이동.

### 빈 / 로딩 / 에러 (DS-4.1 공통 컴포넌트 참조)
| 상태 | 표현 |
|------|------|
| **로딩(초기)** | 지도 위 중앙 스피너 + "전 인원 위치 불러오는 중". 신고목록/보드는 스켈레톤 3행. |
| **빈 — 신고 0** | 신고목록 패널: "아직 접수된 신고가 없습니다" 일러스트. |
| **빈 — 인원 0** | 지도 중앙 "현재 공유중인 인원이 없습니다". |
| **빈 — 행사 미선택** | 전체 영역에 "관제할 행사를 선택하세요" + 드롭다운 강조. |
| **에러 — WS 끊김** | 헤더 인디케이터 amber 전환 + 상단 슬림 배너 "실시간 연결 끊김 · 폴링으로 갱신중"(기존 35행 green/amber 패턴 재사용). 지도는 폴링 데이터로 계속 동작. |
| **에러 — 지도 SDK 실패** | 지도 영역에 "지도를 불러오지 못했습니다 · 새로고침" 재시도 버튼. |
| **에러 — 권한 403** | controller/admin 아니면 진입 차단 화면(§7 가드). |

## 7. 신고자 연락처 노출 규칙 (ADR-0004 강제)

관제는 controller/admin 화면이라 연락처 **노출 허용**. 단 **노출 지점을 최소화**:

| 위치 | 연락처 | 비고 |
|------|--------|------|
| 신고 접수 목록 **행(접힘)** | ❌ 미표시 | 유형·시각·상태·[배정]만. 이름 노출도 최소(또는 마스킹). |
| 신고 행 **펼침 / 상세 모달** | ✅ 이름·연락처 | `request.created` 페이로드 `requester:{id,name,phone}`(SPEC-05b) 사용. 클릭해 펼친 controller만 봄. |
| 지도 **신고핀 인포윈도** | ✅ 이름·연락처 + [전화 tel:] | 신고핀 클릭 시. 관제 화면 내부라 허용. |
| 지도 **인원 마커 인포윈도** | ❌ 연락처 없음 | `participant.location` 페이로드엔 `user_id,role`만(SPEC-05b) — **연락처 키 자체가 안 옴**. 마커 인포윈도는 이름(있으면)·역할·online만. |
| 출동 현황 보드 | ❌ 연락처 없음 | `dispatch.updated` 페이로드에 연락처 없음(SPEC-05b). 대원/상태/시각만. |

- **가드(진입)**: 관제 페이지는 서버 미들웨어(`controller` 또는 시스템 `admin`)로 차단(02/07). 채널 `event.{id}.control` 인가도 동일(SPEC-05a). FE는 진입 후 추가로 연락처 UI를 위 표대로만 렌더.
- **회귀 방지**: 인원 마커 인포윈도 컴포넌트에 **연락처 슬롯을 두지 않는다**(페이로드에 없으므로 실수로 표시할 수도 없게). 연락처는 신고(control 페이로드) 컨텍스트에서만 컴포넌트가 받는다.

## 9. FE 결정 잔여 (디자이너 위임 가능 — 구현 편의 우선)

1. **신고핀 ↔ 출동대원 경로 폴리라인 표시 범위**: en_route만 그릴지 / arrived까지 유지할지(도착 후엔 정보가치 낮음). 권장: `en_route`만, `arrived` 시 폴리라인 제거하고 핀에 ✓ 표시. 성능(다수 동시 출동 시 폴리라인 수)도 FE가 실측해 상한 결정.
2. **오프라인(>120s) 마커 기본 처리**: 흐리게 유지 vs 자동 제거. 권장: 기본 "흐리게 유지" + L-RAIL에 "오프라인 숨기기" 토글 제공(수천 규모에서 잔상 누적되면 제거 쪽으로). 임계(120s)는 R1/R2 부하테스트 결과로 조정 가능.
