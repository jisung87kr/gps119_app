## 0. 공통 토큰 (전 DS-3.x 참조)

### RequestType 4종 — 색 / 아이콘 / 라벨 (`RequestType::markerIcon()`·`badgeClasses()`)
신고 버튼·핀·뱃지 모두 이 1세트로. **기존 `RequestPriority::badgeClasses()` 팔레트와 일관**(slate/sky/orange/red).

| RequestType | 라벨 | 버튼/핀 색 hex | Tailwind 뱃지 | 아이콘(Heroicon) | 기본 priority(SPEC-02c) |
|-------------|------|----------------|---------------|------------------|--------------------------|
| `accident` | 사고 | `#EA580C` orange-600 | `bg-orange-50 text-orange-700` | `exclamation-triangle` | HIGH |
| `breakdown` | 고장 | `#F59E0B` amber-500 | `bg-amber-50 text-amber-700` | `wrench` | MEDIUM |
| `other` | 기타 | `#6B7280` gray-500 | `bg-slate-100 text-slate-600` | `ellipsis-horizontal-circle` | LOW |
| `emergency` | 긴급전화 | `#DC2626` red-600 | `bg-red-50 text-red-700` | `phone` (수화기) | CRITICAL |

- **사고/긴급 색맹 분리**: 둘 다 빨강 계열 → 아이콘으로 결정 분리(사고=⚠ 삼각, 긴급=☎ 수화기). 긴급은 신고 흐름이 아예 다름(§DS-3.1 즉시 tel:).
- 색만 의존 금지: 버튼·뱃지·핀 전부 **아이콘 + 한글 라벨** 병기.

### DispatchStatus 6종 — 뱃지 / 전이 라벨 (`DispatchStatus::badgeClasses()`·`label()`, SPEC-02d)

## DS-3.1 — 주소확인 모달 + 신고 버튼 (참가자 앱)

### 신고 동선 (05 흐름 3~8, `RequestMapApp.js` 확장)
```
[사고🟠]  [고장🟡]  [기타⚪]  [긴급전화🔴]   ← 바텀시트 하단, 4버튼 그리드
   │ (사고/고장/기타)                  │ (긴급)
   ▼                                   ▼
getCurrentPositionOnce → 역지오코딩    즉시 tel: (모달 없음)
   ▼                                   (행사 구조본부 번호 projects.settings)
"이 위치가 맞습니까?" 모달  ← 핵심: 기존 confirm('위치공유...') 146행 대체
   │ [이 위치로 신고]
   ▼
POST /api/requests { type, latitude, longitude, address, project_id, contact_phone }
   ▼
신고 접수 완료 화면 → 담당자/상황실 tel: 버튼
```

### 신고 버튼 (4종)
- 바텀시트 하단 `grid grid-cols-4 gap-2`(또는 사고/고장/기타 3칸 + 긴급 풀폭 강조). 각 버튼 = `RequestType` 색 배경 + 흰 아이콘 + 라벨. 한 손 도달 영역, 오탭 방지 `gap`, `:active` 스케일(기존 `.emergency-btn` 톤, create.blade.php 19행 계승).
- **긴급전화 버튼 시각 차별화**: 다른 3개와 분리(테두리 강조 또는 풀폭), 누르면 모달 없이 즉시 `tel:` — 누른 즉시 통화임을 라벨에 "📞 즉시 통화" 명시.
- 전송 시 `type`(enum) 전송. 기존 free-text `description`→`type` 교체(05/SPEC-02c).

### "이 위치가 맞습니까?" 모달 (이 태스크의 심장)
```
┌─────────────────────────────────┐
│  이 위치가 맞습니까?         [✕] │
├─────────────────────────────────┤
│  ┌───────────────────────────┐  │
│  │   지도 미리보기 (핀 고정)   │  │ ← 카카오맵 mini, 핀 중앙
│  │   [핀 드래그로 보정 가능]   │  │
│  └───────────────────────────┘  │
│  📍 서울 노원구 동일로 1342      │ ← 역지오코딩 주소(크게 font-bold)
│     (상세주소/건물명)            │
│  ⚠ 위치 정확도 낮음 — 지도 확인  │ ← accuracy 큰 값일 때만
│  [ 주소 다시 검색 ]              │ ← 기존 daum postcode 재사용
├─────────────────────────────────┤
│  [   취소   ]   [ 이 위치로 신고 ]│ ← 우측 primary(유형 색)
└─────────────────────────────────┘
```
- 구성: ① 주소 텍스트(`text-lg font-bold`, 화면 최상위 정보) ② 지도 미리보기 + 드래그 보정(드래그 시 역지오코딩 재실행) ③ 주소 재검색(기존 daum postcode 임베드 재사용) ④ [취소]/[이 위치로 신고](primary = 선택한 type 색).
- **모달 상태**:
  | 상태 | 표현 |
  |------|------|
  | 역지오코딩 로딩 | 주소 자리 스켈레톤 + "주소 변환 중…" |
  | 역지오코딩 실패 | 주소 못 찾음 → 좌표(위경도) 표시 + 수동주소 입력 폴백, **신고는 가능**(주소 없이 좌표로) |
  | GPS 저정확도(accuracy 큰 값) | ⚠ "위치 정확도 낮음, 지도에서 확인" 경고 + 보정 유도 |
  | 전송 중 | [이 위치로 신고] 버튼 스피너·비활성(중복 전송 방지) |
  | 전송 실패 | 모달 유지 + 인라인 에러 "전송 실패, 다시 시도" |

### 접수 완료 화면
- "신고가 접수되었습니다" 확정 피드백 + 신고 위치 재확인(고정좌표) + [내 신고 상태 보기](→ DS-3.4).
- **담당자 tel: 버튼**: 배정 전 = 상황실 대표번호, 배정 후 = 담당 구급대원(DS-3.4에서 실시간 전환). 공백 없이 항상 통화 가능.

### 수용 기준
- [ ] 신고 전 모달에 **주소 텍스트 표시**(05 수용기준). 단순 confirm 아님.
- [ ] 역지오코딩 실패/저정확도에도 신고가 막히지 않음.
- [ ] 긴급전화는 모달 없이 즉시 tel:.
- [ ] `type` enum 전송, 좌표는 신고 시점 고정(03 불변).

## DS-3.2 — 지령 배정 + 출동현황 보드 (관제 SPA)

control-map-spec의 **BOTTOM 영역**(신고목록 flex3 / 출동보드 flex2)에 안착. 신고 클릭 → 배정 패널.

### 지령 배정 패널 (신고 클릭 시)
```
신고목록 #12 [사고] 12:03 [배정▸] ─클릭→ 우측 슬라이드 패널 or 모달
┌─ 지령 배정 — 신고 #12 (사고) ──────────────┐
│ 📍 동일로 1342  ·  신고자 홍길동 010-…(관제) │ ← 관제는 연락처 노출(ADR-0004)
│ 가용 구급대원 (online · 거리순)             │
│ ┌────────────────────────────────────────┐ │
│ │ ○ 김구급  120m   [지령0]  ←거리+보유배지 │ │ Q3: 거리우선 정렬 + 보유지령수 배지
│ │ ○ 이구급  340m   [지령1]                │ │
│ │ ○ 박자봉  510m   [지령0] (자봉구급)      │ │
│ └────────────────────────────────────────┘ │
│ 메모: [_______________________]            │
│              [ 취소 ]  [ 지령 발령 ]        │
└────────────────────────────────────────────┘
```
- **가용 구급대원 리스트 표시 항목**: ① 이름 ② 신고 고정좌표까지 **거리(m/km)** ③ **현재 보유 활성 지령수 배지**(`[지령 N]`) ④ 역할(구급대/자봉구급 구분) ⑤ online dot. 대상 = `canReceiveDispatch()` true(paramedic·volunteer_medic) AND online.
- **정렬(Q3 권장안)**: **거리 오름차순 우선**, 보유 지령수는 **배지로 보조 표시**(정렬 키 아님). 보유 많은 대원은 배지 색 경고(`[지령 2]` amber)로 과부하 시각화 — controller가 거리 가깝지만 바쁜 대원을 피할 판단 근거.
- 대상 선택(라디오) + 메모 → `POST /api/requests/{id}/dispatch { paramedic_id, note }`. 발령 후 신고행 상태 `[배정]`, 지도 대원 마커에 배정 표시(control-map-spec §3 출동중 마커).
- **빈/에러**: 가용 0명 → "배정 가능한 구급대원이 없습니다(전체 호출/대기 안내)". 발령 실패 재시도. 동시 배정 경합(OI-2) 시 422 → "이미 배정된 신고" 안내·리스트 갱신.

### 출동 현황 보드 (BOTTOM 우측 flex2)
```
┌─ 출동 현황 ───────────────────────────┐
│  배정 2   출동 1   도착 0   완료 5     │ ← DispatchStatus 카운트(실시간)
├───────────────────────────────────────┤
│ #12 사고  배정→수락 12:05  (김구급)    │ ← 활성 지령 타임라인
│ #11 고장  출동 11:52       (이구급)    │
│ ── 완료 이력 ──                        │
│ #07 사고  접수12:40→도착12:51→완료13:02│ ← 처리시간 표기
└───────────────────────────────────────┘
```
- 상단 카운트 4종(배정/출동/도착/완료) = `DispatchStatus` 색 칩, `dispatch.updated` 실시간 증감(SPEC-05b).
- 활성 지령 = 타임라인 행(현 상태 뱃지 + 직전 전이 시각 + 담당대원명). 완료 지령은 **이력 섹션으로 이동**, 처리시간(접수→도착→완료) 표기.
- **재배정/거절 표시**: `rejected` 수신 시 해당 신고 "거절됨 — 재지령 필요" 경고행으로 복귀(신고 status는 pending 유지, SPEC-02d 동기화표), [재배정] CTA로 배정 패널 재오픈. 무응답(타임아웃) 시 동일 경고.
- 연락처: 관제 화면이라 신고 상세/배정 패널에 노출 허용. 출동보드 행 자체엔 연락처 없음(대원명·상태·시각만).

### 수용 기준
- [ ] 거리순 + 보유지령수 배지로 대원 선택해 배정.
- [ ] 가용 0명·거절·무응답(재배정) 상태 정의.
- [ ] 배정/출동/도착/완료 실시간 카운트 + 처리시간.

## DS-3.3 — 구급대원 지령 화면 (앱)

### 1. 지령 풀스크린 알림
- `event.{projectId}.dispatch.{userId}` 구독 → `dispatch.assigned` 수신 시 **풀스크린 점유**.
- **알림음/진동 트리거 지점**: Echo 콜백 `.listen('dispatch.assigned', cb)` 내부 첫 줄에서 ① `navigator.vibrate([200,100,200])` ② 알림음 `Audio.play()`. 권한·자동재생 제약 대비: 앱 첫 진입 시 사용자 제스처로 audio unlock(무음 1회 재생). 화면 꺼짐 대비 백그라운드 푸시는 Phase4(FCM).
- **카드 정보**(`dispatch.assigned` 페이로드, SPEC-05b): 신고유형(아이콘+라벨) · 신고 위치(주소 + 지도 미니) · **신고자 이름·연락처(본인 배정건이라 노출, ADR-0004)** + [전화 tel:] · 상황실 메모. 운전·장갑 가정 → 큰 터치타깃(min 56px).

### 2. 상태 전이 버튼 — **현재 상태에서 가능한 다음 전이만 노출** (SPEC-02d 전이표)
잘못된 전이를 **UI에서 원천 차단**. 현재 dispatch.status → 노출 버튼:

| 현재 상태 | 노출 버튼(주) | 노출 버튼(보조) | 비고 |
|-----------|---------------|-----------------|------|
| `assigned` | **[수락]** → accepted | [거절](사유 필수) | 미수락 상태 |
| `accepted` | **[출동]** → en_route | [거절](사유 필수) | 출동 시 카카오내비 제안 |
| `en_route` | **[도착]** → arrived | — (거절 불가) | 현장 이동중 |
| `arrived` | **[완료]** → completed | — | 완료 시 처리메모 입력 |
| `completed`/`rejected` | (없음, 종료) | — | terminal, 이력만 |

- 규칙: `DispatchStatus::allowedTransitions()`가 반환하는 액션만 버튼 렌더. **다음 1개 주 액션을 크게(primary)**, 거절은 작게(보조, assigned/accepted에서만). 지나온 단계는 타임스탬프 표시(`수락 12:05 · 출동 12:07`).
- 전이 호출: `PATCH /api/dispatches/{id}/status { status, note? }`. 멱등(OI-6): 동일 상태 재전송은 서버가 no-op 200 → **버튼 연타 시 에러 안 뜨고 무시**(현 상태 유지, 버튼은 전이 후 즉시 비활성·다음 버튼으로 교체).
- 전이 실패(422, 잘못된 전이/경합) → 인라인 토스트 "처리할 수 없는 상태입니다" + 서버 최신상태로 버튼 재계산.

### 3. 거절 사유 필수 모달
```
┌─ 지령 거절 ──────────────┐
│ 거절 사유를 선택하세요    │
│ ○ 이미 다른 출동중        │ ← 프리셋
│ ○ 거리가 너무 멂          │
│ ○ 장비/인력 부족          │
│ ○ 기타: [__________]      │
│        [취소] [거절 제출] │ ← 사유 없으면 비활성
└──────────────────────────┘
```
- 사유 미선택 시 [거절 제출] 비활성(필수). 제출 → `status: rejected, note: 사유`. 거절은 `assigned`/`accepted`에서만 노출(en_route/arrived는 버튼 자체 없음).

### 4. "출동" → 카카오내비 딥링크
- [출동] 누르면 en_route 전이 + **카카오내비 자동 제안**. 신고 **고정 스냅샷 좌표**로(신고자 실시간 위치 아님 — 06/03 강조): `kakaonavi://navigate?...`(고정 lat/lng). 앱 미설치 → 카카오맵 길찾기 웹 폴백.
- 도착 후에도 [길안내 다시] 버튼 유지(현장 재확인).

### 수용 기준

## DS-3.4 — 신고자 상태추적 (참가자 앱)

- `event.{projectId}.requester.{userId}` 구독 → `request.status.updated`(SPEC-05b)로 실시간 갱신. 기존 `RequestShowApp.js` 확장.

### 상태 타임라인 (대기→진행→완료)
```
┌─ 내 신고 #12 (사고) ──────────────┐
│ ●━━━━━●━━━━━○━━━━━○               │
│ 접수   배정   출동   완료          │ ← 현 단계 강조, 시각 표기
│ ─────────────────────────────────│
│ 담당 구급대원: 김구급             │ ← 배정 후 노출
│ [ 📞 담당자에게 전화 ]            │ ← tel: paramedic_phone
│ [ 신고 위치 지도 보기 ]           │ ← 카카오맵/내비(고정좌표)
└──────────────────────────────────┘
```
- 단계: 접수(pending)→배정/진행(in_progress, dispatch accepted/en_route/arrived 세부 매핑)→완료(completed). DispatchStatus를 신고자용으로 단순화(배정/출동/도착 → "구조대 진행중" 묶고 세부 시각은 부가).
- **담당자 전화연결**: 배정 전 = **상황실 대표번호**(공백 없음), 배정 후 = `dispatch.paramedic_phone`로 실시간 전환 + 담당자 이름. 신고자는 **자기 신고 담당자 번호만** 봄(ADR-0004, requester 채널엔 담당자 정보만).
- 신고 위치: 고정좌표를 카카오맵 보기 / 카카오내비 길안내(기존 show 화면 확장).
- **자가취소 불가 정책**: 취소 버튼 대신 "취소가 필요하면 상황실로 전화" 안내(기존 도메인 정책 계승).
- **상태/에러**: WS 끊김 → 폴링 폴백 + "갱신 지연중" 슬림 배너(control-map 톤 일관). 완료 시 "구조가 완료되었습니다" 확정 표시.

### 수용 기준
- [ ] 대기/진행/완료 실시간 추적 + 끊김 시 폴백.
- [ ] 배정 전/후 전화 대상(상황실→담당자) 자연 전환.
- [ ] 담당자 정보만 노출(타 인원 연락처 없음).

## FE 결정 잔여 (디자이너 위임 가능)

1. **신고자 타임라인의 dispatch 세부 단계 노출 깊이**: 신고자에게 배정/수락/출동/도착 4단계를 다 보여줄지 vs "접수→구조대 진행중→완료" 3단계로 묶을지. 권장: **3단계로 묶고** 세부 전이시각은 펼침(접힘 기본) — 신고자는 "오고 있다/도착했다"만 직관적으로 알면 됨. 과한 상태노출은 불안 유발.
2. **배정 패널 형태(관제)**: 우측 슬라이드 패널 vs 중앙 모달. 권장: **우측 슬라이드 패널**(지도·신고핀을 보면서 거리 판단 가능, 모달은 지도를 가림). 단 BOTTOM 영역 높이 제약 시 모달 폴백 — FE가 실측해 결정.
