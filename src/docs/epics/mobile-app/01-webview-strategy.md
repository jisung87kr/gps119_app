# 01. 웹뷰 전략 — 무엇을 감쌀 것인가

## 1. 결론 먼저

**Capacitor + «원격 URL 로딩»** 을 권고한다. 즉 앱 번들에 웹 자산을 넣지 않고, 웹뷰가 `https://app.gps119.co.kr` 을 직접 연다. 네이티브 플러그인(위치·푸시·권한)만 앱이 제공한다.

이유는 하나로 요약된다 — **오리진이 웹과 같아지므로 인증·Reverb·쿠키·CSRF 가 아무것도 바뀌지 않는다.**

## 2. 왜 이게 핵심인가: 오리진 문제

현재 API 인증은 **Sanctum SPA 모드 하나뿐**이다.

```
config/sanctum.php:18   'stateful' => 'localhost,...,app.gps119.co.kr:9050'
routes/api.php:15       Route::middleware('auth:sanctum')->group(...)  ← 전 API
```

🔴 **저장소 전체에 `createToken` 호출이 0건이다.** 베어러 토큰 발급 엔드포인트가 없다는 뜻이고, 따라서 **세션 쿠키가 실리지 않는 순간 API 가 전부 401 이 된다.**

### 로컬 번들 방식(기본 Capacitor)이 깨뜨리는 것

Capacitor 기본 설정은 앱 안의 자산을 이런 오리진에서 띄운다.

| 플랫폼 | 웹뷰 오리진 |
|---|---|
| iOS | `capacitor://localhost` |
| Android | `https://localhost` |

`app.gps119.co.kr` 세션 쿠키는 **이 오리진으로 전송되지 않는다.** 영향:

| 깨지는 것 | 왜 |
|---|---|
| `/api/*` 전체 | `auth:sanctum` 이 세션을 못 찾음 |
| **`/broadcasting/auth`** | private/presence 채널 인가 실패 → **실시간이 통째로 죽는다.** 관제·지령·위치 브로드캐스트 전부 |
| 관제 CSV 다운로드 | `ControlApp.js` 가 세션 쿠키 GET 에 의존 |
| CSRF 토큰 | `<meta name="csrf-token">` 이 로컬 문서에는 서버가 심어줄 수 없음 |

이걸 로컬 번들로 밀고 가려면 **토큰 인증 체계를 새로 깔아야 한다** — 발급/저장(Keychain·Keystore)/갱신/폐기 + `/broadcasting/auth` 의 토큰 경로 + CORS. 적지 않은 일이고, **이 에픽의 목적(위치·푸시·유통)과 무관한 비용**이다.

## 3. 3안 비교

| | A. Capacitor + 원격 URL | B. Capacitor + 로컬 번들 | C. 네이티브 셸 직접 작성 |
|---|---|---|---|
| **오리진** | 웹과 동일 → **변경 0** | `capacitor://localhost` → 인증 재설계 | 동일하게 만들 수 있음 |
| **인증·Reverb** | 그대로 동작 | 토큰 체계 신설 필요 | 그대로 동작 |
| **배포 주기** | **웹 배포 = 앱 갱신** (스토어 심사 없이 즉시) | 웹 변경마다 스토어 재심사 | 웹 배포 = 앱 갱신 |
| **오프라인** | 🔴 약함 — 네트워크 없으면 빈 화면 | 강함 | 약함 |
| **초기 로딩** | 네트워크 의존 | 즉시 | 네트워크 의존 |
| **스토어 심사 리스크** | 🔴 **높음** — "웹사이트 래퍼"로 보이기 쉬움(App Store 4.2) | 중간 | 높음 |
| **플러그인 생태계** | 풍부 | 풍부 | 직접 구현 |
| **공수** | 낮음 | 중간~높음 | 높음 |

**C 를 버리는 이유:** 얻는 게 «플러그인을 직접 짤 자유»뿐인데, 필요한 플러그인(위치·푸시·권한)이 전부 Capacitor 에 이미 있다.

**B 를 버리는 이유:** 오프라인 이점이 실익이 없다. GPS119 는 **네트워크가 없으면 애초에 목적을 달성 못 하는 서비스**다 — 구조요청은 서버에 닿아야 하고, 관제는 실시간이어야 한다. 오프라인에서 캐시된 지도를 보는 것에 인증 재설계 비용을 지불할 이유가 없다.

## 4. A안의 대가 — 정직하게

### 4-1. 🔴 App Store 4.2 (Minimum Functionality) 리스크가 가장 크다

원격 URL 만 띄우는 앱은 **"웹사이트를 다시 포장한 것"** 으로 리젝되는 대표 유형이다. 완화책:

- **네이티브 기능을 실제로 쓰고, 그것이 앱의 존재 이유임을 설명한다** — 백그라운드 위치 추적·푸시 알림은 웹이 못 한다. 이 에픽의 목적 자체가 방어 논리다
- 스플래시·앱 아이콘·네이티브 권한 다이얼로그·오프라인 폴백 화면을 갖춘다
- 심사 노트에 **"행사 현장 안전관제용 앱. 백그라운드 위치와 푸시가 핵심 기능이며 웹으로 대체 불가"** 를 명시
- → 상세: [`05-store-release.md`](05-store-release.md)

### 4-2. 네트워크 단절 시 빈 화면

Capacitor `errorPath` 로 로컬 오프라인 화면을 지정한다. 기존 `public/offline.html` 을 셸에 복제해 재사용.

### 4-3. 앱 갱신이 «심사 없이» 되는 것은 양날

장점이지만, **스토어 심사를 우회해 기능을 바꾸는 것으로 보이면** 그 자체가 정책 위반 소지다. 실무 기준: **UI/버그 수정은 웹 배포로, 권한·과금·핵심 기능 변경은 앱 버전과 함께.**

## 5. 구현 메모

```
gps119_app_mobile/            ← 별도 레포 (06 참조)
├── capacitor.config.ts
│     server.url = https://app.gps119.co.kr
│     server.androidScheme = https
│     server.errorPath = offline.html
├── ios/  android/            ← 네이티브 프로젝트
└── src/offline.html          ← 유일한 로컬 자산
```

**웹 쪽에서 해야 할 일 (`src/` 레포):**

| 항목 | 이유 |
|---|---|
| `window.Capacitor` 존재 여부로 «앱 모드» 감지 | 앱에서만 네이티브 위치/푸시 사용, 웹에서는 기존 경로 유지 |
| 앱 모드에서 `resources/js/pwa.js` 의 SW 등록 스킵 | 웹뷰에서 SW 와 네이티브 캐시가 겹칠 이유 없음 |
| 네이티브 브리지 어댑터 1개 (`resources/js/native/bridge.js`) | 위치·푸시·권한 호출을 한 곳에 모아 **웹 코드가 Capacitor 를 직접 알지 않게** 한다. 나중에 셸을 바꿔도 여기만 교체 |
| `SANCTUM_STATEFUL_DOMAINS` 에 실제 앱 도메인 확인 | 현재 `app.gps119.co.kr:9050` — **포트가 붙어 있다.** 운영 도메인이 443 이면 불일치 |

🔴 **마지막 항목은 지금 확인이 필요하다.** `config/sanctum.php:18` 의 기본값에 `app.gps119.co.kr:9050` 가 하드코딩되어 있는데, 운영에서 `.env` 로 덮고 있는지 확인되지 않았다.
