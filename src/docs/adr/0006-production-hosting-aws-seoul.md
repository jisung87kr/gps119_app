# ADR-0006. 운영 배포 대상 — AWS 서울 단일 VM (공공 진입 시 NCP 이전)

- 상태: Accepted
- 날짜: 2026-08-10
- 관련: [`../../../DEPLOY.md`](../../../DEPLOY.md), `epics/realtime-dispatch-control/backlog/infra-tasks.md`(OI-A·OI-B·OPS-08), [ADR-0001](0001-realtime-transport-laravel-reverb.md)

## 배경 (Context)

실서버를 어디에 둘지 정해야 했다. 이 앱의 제약은 일반적인 웹앱과 다르다.

1. **상시 프로세스가 둘이다.** Reverb 데몬(WebSocket)과 큐 워커가 24시간 살아 있어야 한다.
   요청 단위로 뜨고 죽는 실행 모델과는 맞지 않는다.
2. **다루는 데이터가 실시간 위치 이력이다.** `location_pings` + 참가자 실명·전화번호.
   저장 위치가 곧 법적 쟁점이 된다(개인정보 국외이전, 위치정보사업 신고 — 모바일 에픽 N0 블로커).
3. **고객에 공공이 포함된다.** 지자체 축제·마라톤 주최가 사업 대상이다.
4. 유료 고객 이전 단계라 비용이 실질 제약이다.

## 결정 (Decision)

**AWS Lightsail 서울 리전, 단일 인스턴스 + `docker compose`.** 상시 스테이징 서버는 두지 않는다.

- 구성: `docker-compose.prod.yml`(개발용과 별도 파일), `docker/apache/apache-prod.conf`, `deploy.sh`
- TLS: **Let's Encrypt**(최초 발급 standalone → 갱신 webroot). **OI-A 해소.**
- DB: 컨테이너 MySQL + 덤프 백업. 관리형 DB는 유료 고객 확보 후 재검토
- 이미지 레지스트리·CI 없이 서버에서 git checkout + 바인드마운트(OI-B가 열려 있는 동안의 잠정)

### 탈락한 후보와 이유

| 후보 | 탈락 사유 |
|---|---|
| 서버리스(Vercel 등) | Reverb 데몬·큐 워커가 상시 필요. 구조적으로 불가 |
| Railway | 기술 적합성은 높다(4서비스 이식, WS, private networking으로 동일 오리진 유지 가능). **최선 리전이 싱가포르** — 아래 「국외 저장」과 같은 문제. 비용도 단일 VM의 2배 이상 |
| 해외 VM(Hetzner 등) | 국외 저장 + 왕복 250ms |
| NCP / NHN Cloud | **지금은 과하다.** 공공 계약이 실재하기 전까지 얻는 게 CSAP뿐인데 비용은 더 든다 |

### 공공(CSAP)을 지금 따라가지 않는 이유

AWS 서울은 2025-04 CSAP를 받았다(MS·구글도 앞서 취득). **다만 셋 다 「하」등급**이고,
하등급의 정의가 *개인정보를 포함하지 않은, 공개된 공공 데이터를 운영하는 시스템* 이다.
GPS119는 실명·전화번호·실시간 위치 이력을 다루므로 **정의상 하등급 범위 밖**이다.
필요한 것은 중등급인데 중·상 등급은 아직 고시 미반영이고 물리적 망분리를 요구해서,
현재로선 국내 CSP만 충족한다.

즉 **AWS의 CSAP 보유는 이 앱에 대해서는 효력이 없다.** 공공에 팔려면 NCP로 옮겨야 한다.

### 🔑 NCP 이전 트리거 — 「계약 확정」이 아니다

**공공을 진지하게 영업 대상에 넣는 시점**에 이전 + CSAP SaaS 표준등급 심사를 착수한다.

서버 이전 자체는 도커라 반나절이지만, **CSAP SaaS 표준등급 심사가 6개월 이상**이다.
조달 공고를 보고 시작하면 그 건은 이미 놓친 것이다. 이 타이밍 오해가 이 ADR에서 가장
비싼 실수 지점이다.

## 근거 (Rationale)

- 오지 않을 수도 있는 계약을 위해 지금 비싼 인프라를 고르지 않는다. 이전 비용(도커)이 낮아
  「나중에 옮긴다」가 실제로 성립하는 드문 경우다.
- 진짜 이전 비용은 서버가 아니라 **개인정보처리방침·위치정보사업 신고서의 저장 위치를 고치는 서류**다.
  그래서 이전은 «한 번»만 해야 하고, 그 한 번의 타이밍을 위 트리거로 못박는다.
- 국외 리전을 배제하면 저 서류 작업이 애초에 한 겹 줄어든다.

## 결과 (Consequences)

**긍정**
- 단일 VM이라 운영 표면이 작다. 개발용 compose와 구조가 같아 이식·복귀가 쉽다
- OI-A(운영 TLS 발급 경로)가 닫힌다
- 상시 스테이징이 없어 관리 지점이 늘지 않는다 — 로컬 도커가 운영과 동일 구성이라 그 역할을 한다

**부정/비용**
- 공공 진입 시 **이전이 확정적으로 발생한다.** 위 트리거를 놓치면 조달 일정을 못 맞춘다
- 단일 인스턴스라 가용성 이중화가 없다. 인스턴스 장애 = 서비스 중단
- 관리형 DB가 아니라 백업·복구가 사람 손에 달려 있다

**필요 변경 / 남은 것**
- 배포·롤백 리허설 — **로컬 1회 완료(2026-08-10)**, 결함 3건 수정. **실제 인스턴스 리허설은 미실시**
  (실발급 TLS·실도메인·4GB 빌드·재부팅 복귀는 로컬로 대체 불가). OPS-08 은 그때 닫힌다
- 운영 규모 임계(Q4)는 여전히 미확정. 위치 ping 부하 실측(OPS-10) 전까지 인스턴스 사이징은 추정이다
- 앱 셸(`server.url`)을 운영 도메인으로 바꿔 재빌드·스토어 재제출해야 한다

## 재검토 조건

- 공공을 영업 대상에 넣기로 결정한 때 → **NCP 이전 + CSAP 심사 착수**
- OPS-10 부하 결과가 단일 인스턴스 한계를 넘을 때 → 스케일아웃(OPS-09) 또는 상위 인스턴스
- CSAP 중등급 고시가 반영되고 외국 CSP가 취득할 때 → 이 ADR의 전제가 바뀐다
